# 📊 Data Quality Monitor

Система автоматического мониторинга качества данных в распределённых информационных системах с применением статистических методов контроля процессов (SPC).

Разработана в рамках выпускной квалификационной работы 2026 года.

---

## 🔍 О проекте

Система выявляет деградацию качества данных в реальном времени — без участия аналитика и без знания статистики. Агенты мониторинга подключаются к источникам данных, вычисляют пять метрик качества (среднее, стандартное отклонение, медиана, межквартильный размах, полнота) и отправляют их на центральный сервер, который применяет три параллельных статистических метода:

- **Карта Шухарта** — обнаруживает резкие выбросы за границы ±3σ
- **CUSUM** — накапливает малые устойчивые отклонения, невидимые Шухарту
- **EWMA** — сглаживает тренд и показывает направление изменения

Каждый метод решает свою задачу — вместе они покрывают все основные виды деградации данных.

Применение методов соответствует национальным стандартам:
- ГОСТ Р ИСО 7870-1—2022 (общие принципы контрольных карт)
- ГОСТ Р ИСО 7870-2—2015 (карты Шухарта)
- ГОСТ Р ИСО 11462-1—2007 (внедрение SPC)
- ISO/IEC 25012:2008 (модель качества данных)

## 🏗️ Архитектура

Трёхуровневая архитектура с разделением ответственности:

```
Источники данных          Агенты              Сервер              Интерфейс
─────────────────         ──────              ──────              ─────────
PostgreSQL   ──────────►  agent_a.py  ──┐
SQLite       ──────────►  agent_b.py  ──┼──► FastAPI + SPC ──► Streamlit
CSV          ──────────►  agent_c.py  ──┘     PostgreSQL
HTTP-ресурсы ──────────►  live mode  ──────┘                   + Plotly
```

**Уровень сбора данных** — агенты на основе общего базового класса `BaseAgent` с единой функцией `compute_metrics()`, что гарантирует идентичность статистических вычислений независимо от типа источника.

**Уровень агрегации** — FastAPI-сервер с PostgreSQL и SPC-модулем; восемь REST-эндпоинтов с Pydantic-валидацией; четыре таблицы БД (метрики, состояния SPC, журнал событий, конфигурация эксперимента).

**Уровень визуализации** — многостраничное Streamlit-приложение с интерактивными графиками Plotly.

## ⚙️ Установка и запуск

### 1. Требования

- Python 3.13+
- PostgreSQL 18+

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Настройка базы данных

Создайте две базы данных в PostgreSQL:

```sql
CREATE DATABASE data_quality_metrics;  -- для метрик системы
CREATE DATABASE source_a;              -- источник данных A
```

Если нужно — измените параметры подключения в `server/database.py` и `agents/agent_a.py`.

### 4. Запуск сервера

```bash
uvicorn server.main:app --reload
```

Сервер запустится на `http://127.0.0.1:8000`. Интерактивная документация API доступна по адресу `http://127.0.0.1:8000/docs`.

### 5. Запуск веб-интерфейса

В отдельном терминале:

```bash
streamlit run dashboard/app.py
```

Интерфейс откроется на `http://localhost:8501`.

## 🧪 Три режима работы

Откройте страницу **Управление экспериментом** и выберите один из трёх режимов работы.

### Режим 1. Синтетические данные

Система сама генерирует временные ряды и загружает их в три источника. Параметры настраиваются для каждого источника независимо; доступны **11 предустановленных пресетов** типовых сценариев деградации.

### Режим 2. Загрузка из файла

Поддерживается загрузка пользовательских CSV/Excel-файлов с обязательными колонками `timestamp` и `value`. Используется для ретроспективного анализа исторических данных.

### Режим 3. Live-мониторинг

Параллельный опрос трёх внешних HTTP-ресурсов в реальном времени через многопоточность. Каждый источник опрашивается в отдельном потоке Python с управляемым жизненным циклом через `threading.Event` для корректной остановки.

## 📈 Поддерживаемые виды деградации

| Вид | Описание |
|---|---|
| Без деградации | Нормальный режим, только случайный шум |
| Сдвиг среднего | Резкий скачок μ на заданную величину Δ |
| Рост дисперсии | Стандартное отклонение увеличивается на Δσ |
| Пропуски | Доля NaN-значений растёт после заданной записи |
| Постепенный дрейф | Среднее смещается линейно на каждом шаге |
| Случайные выбросы | Отдельные значения резко отклоняются с заданной вероятностью |

## 🧮 Технические особенности SPC-модуля

В модуле `spc.py` реализована **двухфазная модель SPC** (по ГОСТ Р ИСО 11462-1—2007):
- **Фаза I** — накопление параметров baseline через инкрементальный алгоритм Уэлфорда (численно устойчивая оценка σ̂ за один проход)
- **Фаза II** — непрерывный мониторинг тремя методами параллельно

Применены три ключевых технических решения, повышающих корректность:

1. **Алгоритм Уэлфорда** — численно устойчивая оценка дисперсии за один проход, O(1) на обновление
2. **FIR-восстановление CUSUM** (Fast Initial Response) — после срабатывания статистики сбрасываются не в ноль, а в `h/2`, что обеспечивает ускоренное повторное обнаружение
3. **Точная формула σ для EWMA** с поправкой на начальные шаги фазы II — обеспечивает корректные контрольные границы уже с первого наблюдения после baseline

### Параметры SPC (по умолчанию)

| Параметр | Значение | Источник |
|---|---|---|
| `DEFAULT_BASELINE_SIZE` | 50 окон | Montgomery, 2019 |
| `CUSUM_K` | 0.5σ | Стандарт для обнаружения сдвига 1σ |
| `CUSUM_H` | 5.0σ | ARL₀ ≈ 465 |
| `EWMA_LAMBDA` | 0.2 | Lucas-Saccucci, 1990 |
| `EWMA_L` | 3.0 | ARL₀ ≈ 370 |

## 📊 Результаты экспериментального исследования

Проведено пять серий экспериментов:

- **Серии 1–4** — на синтетических данных, 30 повторений каждого сценария (более 150 прогонов суммарно)
- **Серия 5** — на реальных данных сетевой латентности с искусственно созданной нагрузкой

### Основные результаты

| Показатель | Значение |
|---|---|
| Соответствие эмпирического ARL₀ теоретическому | 94% для Шухарта при baseline = 50 |
| Соответствие при baseline = 200 | 80–114% для всех трёх методов |
| Эмпирическое ARL₁ при сдвиге 1σ | Совпадение с теорией в пределах 5% |
| Реакция на live-нагрузку | 7–33 секунды для метрики «среднее» |
| Ложные срабатывания в контрольный период | 0 |
